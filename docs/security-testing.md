# AI 與 API 安全測試

本專案針對提示詞注入、越權存取、資料外洩與幻覺建立可重跑的專項測試。所有測試以正式模式啟動獨立 SQLite，使用虛構帳號、手冊及敏感資料標記，不讀寫運行中的展示或正式資料庫。

2026-10-06 驗證結果：**45／45 個情境檢查通過**（35 個應用層檢查＋8 個本機 Qwen 攻擊情境＋2 個狀態與權限檢查）。完整 pytest 回歸為 **37 項通過**。四類專項測試先於修正前執行並失敗，修正後通過；真實模型使用 `Qwen3-0.6B-Q8_0`。

2026-10-07 加入可重複面試流程及展示工程師登入後，完整 pytest 回歸為 **38 項通過、零失敗、零跳過**，包含上述四類安全測試與偽造展示角色拒絕。45 個情境的真實 Qwen 報告仍是 2026-10-06 的紀錄，沒有將今日一般回歸冒充模型攻擊重測。

同日新增 LoRA 資料分組隔離及引用評分器測試後，完整回歸更新為 **40 項通過、零失敗、零跳過**。LoRA 的少量文件注入題是模型實驗評估，不等同前述 45 個應用層／真實模型安全情境，adapter 尚未通過整套 serving 安全驗收。

## 怎麼重跑

```powershell
# 四組自動化回歸測試，模型輸出由攻擊樣本模擬
.\.venv\Scripts\python.exe -m pytest tests/test_security.py -q

# 產生逐項 JSON 報告
.\.venv\Scripts\python.exe scripts/run_security_checks.py

# 再加本機 Qwen 的 8 個實際攻擊情境；需先啟動 llama.cpp 的 8081 服務
.\.venv\Scripts\python.exe scripts/run_security_checks.py --live
```

如果 Windows 暫存目錄權限異常，pytest 可加 `-p no:cacheprovider --basetemp=.runtime/security-<新的名稱>`，每次用新的路徑，避免覆寫既有測試資料。

逐項結果見 [安全測試報告](../artifacts/security-test-report.json)。報告中的檢查數量是情境斷言數量；pytest 則將四個類別計為四項測試，不應混稱為相同數量。

## 測試內容

| 類別 | 攻擊／測試情境 | 檢查的防線 |
|---|---|---|
| 提示詞注入 | 忽略先前指令、偽造 SYSTEM、要求送出憑證、JSON 邊界逃逸；另將指令藏進實際匯入的手冊 | 後端只接受指定格式的段落選取；額外指令欄位整筆拒絕，引用由原文映射。攻擊不修改案例或使用者角色。 |
| 越權存取 | 未登入讀取、工程師查管理員與稽核資料、偽造主管標頭、讀草稿／撤回案例、發布案例、缺少 CSRF、跨站請求、停用帳號 | 使用真實工作階段與後端權限檢查；正式模式關閉快速登入。 |
| 資料外洩 | 錯誤密碼格式、過長密碼、讀取私有檔案、讀已發布案例的原始快照、讀撤回手冊；檢查模型輸入 | 錯誤回應不回傳輸入或錯誤上下文；工程師僅取得發布欄位；模型輸入不包含資料庫憑證、工作階段、未發布案例或撤回手冊。 |
| 幻覺 | 不存在的引用、錯誤型別、過量選取、無輸出、未知機型、捏造維修處置 | 不合法結果降級為候選來源；接受的摘錄必須存在於來源。AI 案例建議不自動保存。 |

本機模型測試使用相同四種攻擊，每種各測「直接提問」與「文件內藏指令」。必須真的執行模型，不能將模型未啟動或服務失敗算通過；同時核對引用、敏感標記、使用者角色及案例狀態。

## 本次發現與修正

新增測試先在修正前執行，重現以下缺口：

1. 工程師可直接列出、讀取未發布或撤回案例；已發布案例也帶回完整原始快照與修改歷程。現在工程師只能讀已發布的案例欄位；主管保留審核所需的完整資料。
2. 撤回手冊雖已排除檢索，仍能由工程師透過文件 API 讀取。現在工程師的文件清單與明細均排除撤回版本。
3. FastAPI 預設驗證錯誤帶回 `input`，可包含密碼或完整錯誤請求。現在統一保留欄位位置、錯誤類別與通用說明，不回傳原始輸入或上下文。
4. 模型回傳多餘欄位或超過四個段落時，原本仍會接受部分選取。現在後端驗證格式與數量，不依賴模型供應端執行 JSON schema。

## 結果如何解讀

這是有限情境的應用層安全驗證，不是滲透測試認證，也沒有證明模型不會受到所有注入影響。模型可能選到含惡意指令的原文段落；引用有效只代表文字確實在文件裡，不代表指令可信、分類正確或可以執行。維修清單仍須主管核准。

- 未評估真實故障診斷正確率、長對話或多語言攻擊、PDF/OCR 隱藏指令、負載與服務阻斷、PostgreSQL 部署或外部網路攔截。
- 已授權的手冊內容、使用者問題及維修紀錄沒有全面自動遮罩；若人在其中填入敏感資料，仍可能出現在合法回應、模型輸入或稽核紀錄中。
- 工廠內的設備與工單仍依既有協作規則共用；沒有新增多租戶、每台設備或所有工單的逐筆讀取隔離。
- 主管本來就可讀完整案例、文件與稽核；這些授權操作不應被宣稱為「任何角色都讀不到」。
