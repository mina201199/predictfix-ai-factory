# OpenAI 接入與3美金測試上限

金鑰從專案根目錄 `.env` 的 `OPENAI_API_KEY` 讀取，只在後端使用，不傳到前端、不記錄於報告。`.env` 不進版本控制。

本輪使用 `gpt-6-luna` 和 `text-embedding-3-small`。Responses API 只要求模型選取來源段落編號，後端再映射原文；目前沒有自由生成的維修程序或自動派工。工單和設備資料查詢繼續由現有規則與參數化查詢處理。

知識助手加入關鍵字與向量排名融合，依機型、文件有效狀態及案例發布狀態篩選，向量只作候選來源排序。原文引用有效不代表診斷正確。

## 外傳資料範圍

使用者在2026-10-08明確授權只傳 DEMO 虛構資料。
`OPENAI_DOCUMENT_ACCESS=synthetic` 只允許內建虛構段落的編號和內容相符的來源，不能只靠匯入資料的 is_synthetic 標籤取得外傳資格。匯入手冊與維修案例保留本機檢索，未授權時不送模型。未設定時預設 none。

## 預算與失敗處理

- 所有生成與Embedding共用 `.runtime/openai-budget.sqlite`，不因重啟、切換應用資料庫或工程師登入重置。
- `OPENAI_TOTAL_BUDGET_USD` 只接受0到3，較高設定會被阻擋。沒有自動補額度。
- 呼叫前以小型文字請求的保守token上界保留成本，SQLite立即交易避免並行超額。
- 成功回應依usage核算、忽略快取折扣，另加20%保守餘裕；費率來源為2026-10-08查核的官方標準文字費率。
- 逾時、錯誤或usage不明保留完整預留額，不自動重試。預算不足時回到本機候選來源／資料不足回應。
- 不呼叫計費搜尋、影像或其他託管工具。每筆生成最多900輸出token，請求內容有大小限制。
- 重複來源與問題向量使用本機快取；每次檢索仍從有效來源重新篩選，撤回資料不會因向量快取重新出現。

這是本專案呼叫的保守成本帳，不是OpenAI帳號餘額或正式帳單，無法涵蓋其他程式使用相同金鑰的費用。不要刪除預算資料庫以重新取得額度。

## 檢查

主管可讀 `GET /api/openai/budget`；健康檢查不發計費請求。
`scripts/check_openai_access.py` 只查詢模型存取，不印金鑰。
`scripts/smoke_openai_synthetic.py` 只傳送這次新編寫的虛構字串。
`scripts/evaluate_openai_demo.py` 使用獨立應用資料庫，來源強制限內建虛構手冊，仍共用3美金帳。
測試套件停用真實API，預算並行鎖、費用核算、無usage與向量快取以模擬回應驗證。

模型與索引尚未以真實工廠題庫驗收，不將小型示範測試宣稱為現場回答正確率。

## 本輪結果（2026-10-08）

- 8094 DEMO 已套用 OpenAI；實際頁面查詢成功，顯示原文來源與主管可見的估算用量。
- 8 個固定虛構資料檢查通過（3 個 API 段落選取、2 個無來源問題、3 個資料查詢／流程／資訊不足檢查）。這是功能檢查，並非模型診斷正確率。
- 預算、資料授權、維修流程與既有 API 回歸測試共 39 項通過。
- 本輪最終累計保守估算 US$0.001460，剩餘 US$2.998540；不刻意耗盡 3 美元。
- 桌面文字對比與 390px 手機版面檢查通過。金鑰未出現在報告或前端。
