# 維修知識圖譜設計

本子系統採使用者已核准的 SQLAlchemy 輕量有向圖，不另架服務、不呼叫 GPU。沿用 store.Base，新增 graph_nodes 與 graph_relations。原搜尋器不變，獨立 /api/graph/assist 比較字詞檢索與圖譜擴展。

## 來源與生命週期

每條關係保存節點、類型、明確適用機型、來源 ID／段落／版本、完整來源 SHA256、逐字引文、候選建立者與時間、核准／撤回者與時間、審查註記、樂觀鎖 revision。來源重新讀取 maintenance_ai.buildCorpus()，不用其搜尋快取；手冊撤回、案例撤回／草稿、版本或內容改變，舊邊立即失效。模板以模板 ID 為適用範圍，不能自稱適用任何實際機型。

節點類型包含 machine_model、part、alarm、symptom、fault、cause、inspect_step、verify_step、manual_section、case、spare、qualification。型別與有向關係白名單限制遍歷，最多 3 hop、50 路徑、1000 展開、5000 有效邊、20000 筆關係掃描；失效邊不占有效配額，超限明確標示截斷。節點不獨立對工程師公開，避免草稿名稱外洩。

手冊／案例候選由主管逐字指定來源內的兩端文字與引文，系統檢查 schema、適用機型與引文，再由主管核對語意才核准。不聲稱僅靠子字串驗證能證明因果。模板、已發布案例採確定性規則生成候選；備品／資格僅接受來源明示的需要關係，不由庫存存在或人員履歷推論機型相容性。人工核准不等於原廠認證。

## 查詢與前端

要求明確機型與起點文字；只走核准且當下有效的出邊，不走反向因果。assist 先原 TF-IDF/BM25 fusion，再以原文節點命中擴展，保留各步引用與未知。純檢索模式與圖譜模式可分開執行；不產生自動派工、結案、復機操作。主管來源／候選審核頁與工程師唯讀路徑共用 graph.html，沿用登入、CSRF 與嚴格 CSP。

## 驗證與限制

SQLite 真實持久化測試、API 雙模式權限矩陣、來源撤回／改版／草稿、重建冪等、樂觀鎖、防注入與方向／深度限制。固定合成來源、金標與逐題結果比較 retrieval precision/recall、來源正確性和可答率；結果只代表合成情境，不代表真實維修成效。PostgreSQL 未實際驗證。不修改原維修檢索與 LLM 提示。
