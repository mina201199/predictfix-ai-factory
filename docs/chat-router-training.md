# 問題判讀模型訓練與驗證

已訓練 `zh-maintenance-router-v2`，使用 CPU 的字元 TF-IDF 與 Logistic Regression。這次訓練的是問題意圖與既有文件選取，沒有微調生成式語言模型，也沒有訓練設備健康度或剩餘壽命模型。

## 資料與測試

- 訓練：158 題；驗證：30 題；保留測試：57 題。
- 問法來自原有題庫與自行編寫的情境改寫，不含個資、登入密碼或使用者聊天紀錄。
- 三個集合沒有完全相同的題目；仍共用維修主題與詞彙，不能當作跨廠或獨立專家驗收。
- 固定訓練參數，僅使用驗證集合選擇拒答信心門檻 0.44；沒有依測試集調整權重或超參數。

## 結果

同一批 57 題的分類正確率：舊模型 66.7%，新模型 91.2%。分類正確不代表實際回答正確。

加入實際 API、查詢規則、文件來源與拒答檢查後，回答路由與文件選取正確率：舊模型 56.1%，新模型 68.4%。6 題資訊不足案例均拒答。這個評估只檢查路由和來源選取，不評估維修程序在特定機台上的正確性。

直接把低信心分類當作未知會降低分類測試表現，因此不以分類器單獨決定回答。部署採既有明確規則優先、模型補充同義問法，且必須同時符合主題檢查、信心門檻與既有完整來源。模型不產生新的維修步驟或設備數字。

## 部署與保留

- 舊模型 `artifacts/intent-model.joblib` 保留不變。
- 新模型 `artifacts/chat-router-v2.joblib`。
- 訓練結果 `artifacts/chat-router-report.json`。
- API 逐題結果與未通過題目 `artifacts/chat-router-api-evaluation.json`。
- 僅在 API 評估通過、且模型 SHA-256 與評估紀錄一致時載入新版；否則回到舊版。
- 現有數值篩選、來源查核、設備不明追問與資訊不足拒答仍保留。

## 重跑

先執行 `scripts/train_chat_router.py`，再執行 `scripts/evaluate_chat_router.py`。API 評估使用 `.runtime/router-evaluation.db` 的獨立展示資料庫，不修改使用中的工單。

未通過的測試仍保留，不能宣稱已支援所有問題。之後可將失敗案例轉入新版訓練集合，但必須另外建立新的保留測試集，不能用相同測試題宣稱泛化改善。
